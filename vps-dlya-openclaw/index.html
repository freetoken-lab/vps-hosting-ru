Что такое OpenClaw

OpenClaw: персональный AI-агент на вашем сервере

OpenClaw — это платформа для запуска самостоятельного AI-ассистента на собственном сервере. Созданный в конце 2025 года (первоначально под именами ClawdBot и MoltBot), OpenClaw быстро стал одним из самых обсуждаемых open-source AI-проектов: за первые месяцы собрал десятки тысяч звёзд на GitHub и активное сообщество на Reddit.

В отличие от облачных ассистентов, OpenClaw работает на вашем железе — VPS или домашнем сервере. Вы общаетесь с ним через Telegram, WhatsApp, Slack, Discord или другие мессенджеры, а агент выполняет задачи: просматривает веб-страницы, управляет файлами, запускает скрипты, автоматизирует рабочие процессы, взаимодействует с внешними API через систему расширяемых «Skills». Для вывода используются модели Claude, GPT-4, DeepSeek или локальные через Ollama — OpenClaw обеспечивает «тело», а LLM — «мозг».

🤖 Почему VPS, а не домашний компьютер? OpenClaw должен работать 24/7 — принимать сообщения и выполнять задачи даже когда вы спите или ноутбук выключен. VPS в профессиональном дата-центре обеспечивает постоянный аптайм, статический IP и стабильное сетевое соединение без вашего участия.

Требования

Что важно для OpenClaw: CPU, диски, сеть и Anti-DDoS

OpenClaw — не типичное приложение, и его профиль нагрузки отличается от веб-сервера или базы данных. Понимание реальных требований к ресурсам поможет не переплатить за ненужные мощности и не столкнуться с нехваткой RAM в самый неподходящий момент.

Профиль нагрузки OpenClaw: как оценить ресурсы

OpenClaw не выполняет inference на вашем сервере — LLM-запросы уходят в API (Anthropic, OpenAI, DeepSeek). Ваш VPS обрабатывает только: Gateway-процесс, WebSocket-соединения с мессенджерами, работу браузера Chromium (при браузерной автоматизации), файловые операции в workspace агента и Docker-контейнеры. 💡 Ключевой вывод по ресурсам: Стартовые тарифы за 250–370 ₽/мес (512 МБ RAM) не подходят для OpenClaw. Минимальная рабочая конфигурация — 2 vCPU и 4 ГБ RAM. Для браузерной автоматизации с Chromium — 8 ГБ, иначе Chromium будет постоянно убиваться OOM-killer'ом. NVMe диск — не опция, а необходимость: Docker-операции на SATA SSD работают в 3–5 раз медленнее.

Сеть и Anti-DDoS: почему это важно для AI-агента

OpenClaw поддерживает постоянные WebSocket-соединения с серверами Telegram, WhatsApp и других мессенджеров. Это означает, что качество сети важнее, чем для обычного веб-сервера с HTTP-запросами. Нестабильная сеть приведёт к постоянным разрывам соединения и потере сообщений.

Anti-DDoS защита критична по другой причине: агент с публичным IP, особенно если он слушает входящие подключения для Control UI, будет периодически получать мусорный трафик. Базовая L3/L4 фильтрация, которую предоставляют все провайдеры рейтинга, достаточна для защиты личного агента от автоматических атак.

Дополнительная рекомендация из документации OpenClaw: держите Gateway на loopback-адресе и открывайте доступ только через SSH-туннель или Tailscale. Это снижает поверхность атаки до нуля — не нужно открывать никакие порты Control UI наружу.

Как установить OpenClaw на VPS: пошаговое руководство

После получения VPS (Ubuntu 22.04 LTS, минимум 4 ГБ RAM) выполните следующие шаги. Весь процесс займёт 10–15 минут.

1
Подготовьте сервер

Подключитесь по SSH и обновите систему:

$ ssh root@ВАШ_IP
$ apt update && apt upgrade -y && reboot

После перезагрузки установите Node.js 20 LTS и npm — OpenClaw требует Node.js 18+ для работы:

$ curl -fsSL https://deb.nodesource.com/setup_20.x | bash -
$ apt install -y nodejs
2
Установите Docker (необходим для браузерной автоматизации)

Docker нужен для запуска Chromium в изолированной среде и для ряда Skills:

$ curl -fsSL https://get.docker.com | bash
$ usermod -aG docker $USER
3
Установите OpenClaw и запустите онбординг

Установите OpenClaw глобально и запустите встроенный wizard настройки:

$ npm install -g openclaw@latest
$ openclaw onboard --install-daemon

Wizard попросит выбрать: API-ключ модели (Anthropic Claude, OpenAI GPT, DeepSeek или локальная через Ollama), мессенджер для подключения (Telegram, WhatsApp, Slack и др.) и базовые настройки безопасности.

4
Подключите Telegram-бота (или другой мессенджер)

Для подключения Telegram: создайте бота через @BotFather, получите токен и введите его при онбординге. После этого напишите боту в Telegram — агент должен ответить. Для проверки отправьте: Который час?

Для WhatsApp онбординг предложит отсканировать QR-код через приложение WhatsApp на телефоне.

5
Настройте автозапуск и мониторинг

Флаг --install-daemon создаёт systemd-сервис. Убедитесь, что он запущен и настроен на автостарт:

$ systemctl status openclaw
$ systemctl enable openclaw

Проверьте логи при проблемах: journalctl -u openclaw -f

6
Защитите сервер

Настройте файрвол — OpenClaw по умолчанию слушает на loopback, наружу выставлять Control UI не нужно:

$ apt install ufw fail2ban -y
$ ufw allow 2222/tcp && ufw enable
$ sed -i 's/#Port 22/Port 2222/' /etc/ssh/sshd_config && service ssh restart

Для удалённого управления агентом используйте SSH-туннель или Tailscale — не открывайте порты Control UI напрямую.

Оптимизация

Оптимизация VPS для OpenClaw: от ОС до сетевых параметров

Правильная настройка сервера после установки OpenClaw значительно улучшает стабильность и производительность агента. Ниже — практические советы по системному и сетевому тюнингу, бэкапам и типичным ошибкам.

Системный тюнинг: практические советы

  • Swap-файл обязателен: даже при 4 ГБ RAM создайте swap 4–8 ГБ. Chromium и Docker-образы потребляют память пиково — без swap OOM-killer убьёт процесс агента в самый неподходящий момент. fallocate -l 4G /swapfile && mkswap /swapfile && swapon /swapfile
  • Настройте swappiness: добавьте vm.swappiness=10 в /etc/sysctl.conf — это снизит агрессивность использования swap и улучшит отзывчивость при нормальной нагрузке.
  • Дисковое пространство растёт со временем: Docker-образы, логи агента и workspace накапливаются. Настройте ротацию логов через logrotate и ежемесячную очистку неиспользуемых Docker-образов: docker system prune -f
  • Snap-версия Chromium не работает с OpenClaw: на Ubuntu установите Chromium из официального репозитория Google, а не через snap. Snap-изоляция блокирует доступ агента к файловой системе браузера.
  • Ограничьте ресурсы Docker-контейнеров: задайте лимиты памяти в docker-compose, чтобы один упавший контейнер не занял весь RAM сервера.

Сетевой тюнинг: TCP-параметры для WebSocket

OpenClaw использует постоянные WebSocket-соединения. Добавьте в /etc/sysctl.conf следующие параметры для улучшения стабильности долгих соединений:

# Увеличить буферы TCP для WebSocket
net.core.rmem_max = 16777216
net.core.wmem_max = 16777216
# Уменьшить время ожидания для закрытых соединений
net.ipv4.tcp_fin_timeout = 30
# Включить keepalive для обнаружения разрывов
net.ipv4.tcp_keepalive_time = 60
net.ipv4.tcp_keepalive_intvl = 10
net.ipv4.tcp_keepalive_probes = 6

Примените изменения: sysctl -p

Бэкапы и мониторинг агента

Состояние OpenClaw — это его память, конфигурация Skills и файлы workspace. Потеря этих данных означает, что агент «забудет» всё, что узнал. Настройте регулярные бэкапы директории OpenClaw:

  • Директория состояния обычно находится в ~/.openclaw — именно её нужно бэкапить. У провайдеров с автобэкапами (AdminVPS, Beget) это происходит автоматически.
  • Мониторинг процесса: настройте внешний пинг через UptimeRobot или аналог — агент должен периодически отвечать на тестовые сообщения. Если перестал отвечать — systemd или сам агент завис.
  • Репутация IP-адреса важна для браузерной автоматизации. Дата-центровые IP нередко попадают в блок-листы сайтов с Anti-Bot защитой. Если агент активно парсит данные — рассмотрите резидентные прокси (Decodo Skill для OpenClaw) вместо прямого IP сервера.

Типичные ошибки и как их избежать

  • Слишком мало RAM: берут минимальный тариф (512 МБ–1 ГБ) — агент запускается, но Chromium падает при первом же браузерном запросе. Минимум для работы — 4 ГБ.
  • SATA SSD вместо NVMe: Docker-образы тянутся медленно, контейнеры стартуют по 30–60 секунд вместо 3–5. Проверяйте тип диска у провайдера до оплаты.
  • Открытый Control UI наружу: привязка Gateway к 0.0.0.0 без аутентификации — прямой путь к компромиссу агента. Всегда используйте SSH-туннель или Tailscale.
  • Игнорирование лимитов токенов LLM API: агент, оставленный без надзора, может уйти в петлю и потратить значительный бюджет API-токенов за ночь. Устанавливайте лимиты расходов в настройках провайдера модели.
  • Snap-Chromium на Ubuntu: snap-изоляция ломает доступ к профилям браузера. Используйте deb-пакет от Google или устанавливайте Chromium через Docker-образ.
  • Отсутствие мониторинга: агент молча падает, пользователи не получают ответов, а хозяин узнаёт об этом через сутки. Настройте алерты.

Часто задаваемые вопросы

Что такое OpenClaw и зачем ему нужен VPS?
OpenClaw — это open-source платформа для запуска персонального AI-ассистента на собственном сервере. Агент подключается к Telegram, WhatsApp и другим мессенджерам, управляет браузером Chromium для веб-автоматизации и выполняет задачи через расширяемую систему Skills. VPS нужен, потому что агент должен работать 24/7 — принимать сообщения и выполнять задачи даже когда ваш компьютер выключен. Профессиональный дата-центр обеспечивает постоянный аптайм, статичный IP и стабильное сетевое соединение с серверами мессенджеров.
Какие минимальные характеристики VPS нужны для OpenClaw?
Минимальная рабочая конфигурация: 2 vCPU, 4 ГБ RAM, 40 ГБ NVMe, Ubuntu 22.04. Стартовые тарифы с 512 МБ–1 ГБ RAM не подходят — этого достаточно только для самого Gateway, но Chromium и Docker-образы потребуют значительно больше. Для браузерной автоматизации с одной сессией Chromium — 8 ГБ RAM. NVMe-диск обязателен: Docker-операции на обычном SATA SSD работают в разы медленнее и ухудшают отзывчивость агента.
Что такое VPS с OpenClaw и чем он отличается от обычного хостинга?
VPS с OpenClaw — это виртуальный сервер, на котором развёрнут и круглосуточно работает OpenClaw-агент. В отличие от обычного хостинга, VPS предоставляет root-доступ, возможность установки Docker и Node.js, постоянные процессы и выделенные ресурсы без влияния соседей. Обычный shared-хостинг для OpenClaw не подходит — он не позволяет запускать долгоживущие процессы, устанавливать произвольное ПО и требует KVM-виртуализации для корректной работы Chromium.
Нужна ли GPU для работы OpenClaw?
Нет. OpenClaw не выполняет AI-inference на вашем сервере — LLM-запросы уходят во внешний API (Anthropic Claude, OpenAI GPT или другие). GPU нужна только если вы хотите запускать локальные модели через Ollama непосредственно на своём сервере — это отдельный сценарий, значительно дороже. Для стандартного использования OpenClaw с API-моделями достаточно обычного CPU-сервера с 4–8 ГБ RAM.
Можно ли запустить OpenClaw на российском VPS?
Технически да — OpenClaw работает на любом Linux VPS с Node.js и Docker. Однако есть нюанс: если агент использует браузерную автоматизацию или подключается к мессенджерам, которые ограничены в России (Telegram частично, WhatsApp), лучше разместить его на зарубежном VPS. Провайдеры AdminVPS и is*hosting предлагают серверы в Германии и Нидерландах с оплатой из России — это оптимальный компромисс.
